# AI 模块设计：基金体检报告的「个性化解读层」

> 本文档把基金体检项目升级为「数据分析 + AI 应用」混合项目。
> 定位先说死：**体检打分是数据层，AI 是解读层**——AI 不产生任何结论，它只把算出来的数字翻译成人话。
> 这个定位决定了后面所有设计，也是面试第一问的答案。

---

## 1. 场景：为什么这里需要 AI

用户的真实需求不是"给我一个 43 分"，而是：

> "我每月攒 3000 块，能接受 15% 左右的回撤，帮我看看这只基金适不适合我，或者有没有更合适的。"

这个需求有三个特点，恰好都是传统接口做不到的：

1. **输入是自由文本**（预算、期限、风险偏好、目标），必须先理解意图；
2. **输出是个性化的自然语言**（同一只基金，对保守用户和激进用户的"适合度"叙述完全不同）；
3. **判断必须引用真实数据**——用户要的是理由，不是感觉。

前两条是大模型的主场，第三条是大模型最大的坑（幻觉）。**所以整个模块的设计核心就一句话：让模型只负责"翻译"，不负责"算数"——所有数字都由代码算好喂给它，并明令禁止它使用输入之外的任何数字。**

## 2. 架构：两层分工，责任清晰

```
用户输入（自然语言需求）
        │
        ▼
┌─────────────────────┐
│ 数据层（纯代码，无 AI） │  master.csv：5085 只基金的
│ · 按条件筛选候选产品    │  打分、费率、回撤、分位排名
│ · 算好每一项指标和分位  │  ← 这一层决定了"推荐得对不对"
└─────────┬───────────┘
          ▼  结构化上下文（JSON）
┌─────────────────────┐
│ 解读层（LLM）         │  · 把数字翻译成用户能懂的话
│ · 只许用上下文里的数字  │  · 按用户的风险偏好调整叙述
│ · 禁编造、禁荐股话术    │  ← 这一层决定了"说得像不像人话"
└─────────────────────┘
```

**为什么要分两层**（面试必答）：如果把原始净值序列直接丢给大模型，让它自己算夏普比率——它算不对，而且错得理直气壮。**正确做法是让代码做代码擅长的事（精确计算），模型做模型擅长的事（语言生成）**。这句话本身就是对"你懂 AI 能力边界吗"的回答。

## 3. 「推荐」的合规边界（金融 AI 产品的生死线）

用户嘴上说"推荐基金"，但**产品上不能做"投资建议"**——基金投顾是持牌业务，无牌推荐属于违规。所以设计上做三个转换：

| 用户说 | 产品做 | 为什么 |
| --- | --- | --- |
| "帮我推荐基金" | 按条件**筛选**并**解释差异**："符合你条件的同类产品有 A/B/C，它们在费用和回撤上的差别是……" | 信息呈现，不是投资建议 |
| "这只基金能买吗" | 给**体检结果**："它的费率高于同类 78% 的产品、历史最大回撤 49%"，加免责声明 | 描述事实，不做承诺 |
| 任何输出 | 固定免责声明：数据截至 X 日，不构成投资建议，历史业绩不代表未来 | 合规底线 |

**面试讲法**：这一节能讲出来，说明你知道金融 AI 产品不是"接个大模型"就完了——监管红线先于产品体验。金融科技岗这题几乎必考。

## 4. Prompt 设计原则（迭代记录留给你）

代码骨架里给了 v1 版 Prompt，四条硬规则写死在 system prompt 里：

1. **数字封闭**：只允许使用上下文 JSON 中出现的数字；上下文里没有的信息，回答"暂无数据"；
2. **身份与口吻**：面向没有任何金融背景的普通用户，禁止"夏普比率""年化波动率"这类术语裸奔——要么翻译（"历史上最惨的时候亏 49%"），要么解释；
3. **结构固定**：一句话结论 → 收益 → 风险 → 费用 → 适合谁/不适合谁 → 免责声明（结构固定是为了评测可比）；
4. **合规话术**：全文不得出现"建议买入""可以加仓""预计收益"等表述。

**你要做的迭代**：v1 一定会有毛病（太啰嗦 / 术语没翻译干净 / 把"费率高于 78% 的同类"说反）。跑 → 挑毛病 → 改 → 再跑，把**每一版的 Prompt 和失败样例都留档**——这份迭代记录是 AI PM 面试里最值钱的材料，比最终版本身值钱。

## 5. 评测方案（AI 项目和普通项目的分界线）

AI 输出没有标准答案，所以必须自己定义"好"。评测 4 个维度，每项 0–2 分：

| 维度 | 0 分 | 2 分 | 查什么 |
| --- | --- | --- | --- |
| **数据忠实** | 出现输入里没有的数字（幻觉） | 所有数字可溯源 | 逐个数字对照上下文 JSON |
| **合规** | 出现收益承诺/买入建议 | 有免责声明且无违规表述 | 正则初筛 + 人工复核 |
| **可读性** | 术语裸奔看不懂 | 一个不熟悉基金的人能复述大意 | 找一个非金融的朋友读 |
| **完整** | 漏结构段落 | 六段齐全且不空洞 | 对照固定结构 |

- **样本量**：20–30 条（10 只不同画像的基金 × 2–3 种用户需求），由你逐条打分。
- **目标**：数据忠实性幻觉率 < 5%（30 条里至多 1–2 处）；合规违规 0 条——**合规是硬门槛，出现一次就必须改 Prompt 重跑**。
- **为什么 20–30 条而不是 3 条**：3 条是 demo，30 条才叫评测。这个数量级也只有人工可行，面试时说"我人工标注了 30 条样本"是可信且够用的。

## 6. 成本与延迟

- 用 OpenAI 兼容接口，输入约 1500 token / 次（上下文 + Prompt），输出约 800 token；
- 按智谱 GLM-4-Flash（免费）或 DeepSeek（约 ¥0.001/次）算，**30 条评测 + 迭代的全部成本不到 1 块钱**；
- 单次延迟 2–5 秒——作为"详情页点击'AI 解读'按钮"的交互可接受，不需要流式（写进设计的取舍）。

## 7. 局限（照旧，先自己写进报告）

- 评测集是自建自评，没有第二标注人，一致性未检验（局限，不是漏洞）；
- "筛选候选"目前基于规则（分数、费率、回撤阈值），不是模型做的——**刻意不做**：让模型在几千只产品里直接挑，既不可控也不可解释；
- 用户风险偏好是自述文本，未做问卷校准；
- 模型只做解读层，**"适合谁"的判断逻辑（阈值匹配）仍是规则**——这是 v1 的保守选择，v2 可以探索让模型在给定约束下做匹配并给出可验证的理由链。
