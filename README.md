## 这个项目在解决什么问题

买基金的人面对的信息是**只给数字、不给位置**：页面写着"近三年年化 −18.42%"，但你不查 100 个页面就不知道这算好算坏。

我的判断是：**缺的不是数据，是参照系和翻译层。**

所以项目分成两半：

1. **参照系由代码算**——组内分位、同类排名、"是否超出你的承受线"。这些是确定性计算，算错就是错。
2. **翻译由模型说**——把"分位 0.5"说成"投 10 万，最难受时只剩 5 万"。这是非确定性生成，需要约束。

两半之间有一条明确的边界，见下面「核心设计」。

## 三个主要发现

### 一、"高费低效"的成因不是费率

1,097 只产品（占样本 21.6%）同时满足「综合费率 ≥ 行业标准档」与「卡玛处于组内后 25%」。它们费后年化比其余样本低 **13.07 个百分点**，但综合费率只高出 **0.17 个百分点**——费率仅能解释差距的 **1.3%**。

把结论写成"高费率导致收益差"是错误归因。

### 二、它们是"在错误时点卖出的赛道产品"

该群体相对全样本超配白酒消费 **3.42×**、医药医疗 **2.66×**、新能源 **2.58×**，却低配科技半导体 **0.72×**。集中暴露于特定赛道、并承受了赛道回撤，是比"费率贵"更贴近事实的解释。

### 三、结论只能落在群体上，不能落在个体榜单上

换一套权重后，"最差 100 只"名单只剩 **54–56%** 重合。所以本项目不出"十大最差基金"——那种榜单本质是权重的产物。这是敏感性检验直接给出的产品设计约束。

## 核心设计：模型不许碰算术

30 条抽样测试里，**7 条出现事实错误（23%）**。逐条核对后发现：**没有一条是编造外部数据**，全部是模型在给定数字上算错或理解反——

| 错误类型 | 实例 |
| --- | --- |
| 前提错配 | 用户承受线 30%，模型按 15% 计算并复述 |
| 逻辑反转 | 回撤 10.75% 低于 15% 承受线，却写"超出 34 个百分点" |
| 算术幻觉 | "34"这个数字在上下文里根本不存在 |

对策不是把 Prompt 写得更严厉，而是**把比较和差值下沉到代码**：

```python
# src/card.py 输出的"结论字段"（模型只准原样引用）
"承受线对照": {
    "是否超出承受线": "否",
    "允许的表述": "最大回撤 10.75% 低于你 15% 的承受线，在其承受范围内（余量 4.25 个百分点）",
    "禁止的表述": ["禁止说'超出'", "禁止自行重算差值，只能引用上面这句"]
}
```

模型从此只需要做语言转换，不需要在脑子里做减法。这是把错误率压下去的唯一可靠办法。

## 架构

| 层 | 脚本 | 做什么 | 产物 |
| --- | --- | --- | --- |
| L0 采集 | `step1–3` | akshare 拉全市场基金列表、份额、评级、经理、净值、费率；去重份额、剔除场内 | 6,564 个净值文件 |
| L1 汇总 | `step4`（前半） | 合并基本信息、评级、费率 | 8,146 只基础记录 |
| L2 指标 | `step4` | 11 个候选指标 → 相关性审计 → **7 个独立信号** → 组内分位打分 | 5,085 只（主动 4,109 / 被动 976） |
| L3 画像 | `step5` | K-Means 聚类 + 硬规则圈"高费低效"（两者分离，避免循环论证） | 1,097 只 / 21.6% |
| L4 EDA | `step6` | 8 张图：分布、费率档位、风险收益平面、画像对比、净值曲线 | `reports/figs/` |
| L5 表达 | `card.py` → `step7` / `step8` | 代码出数据卡 → 模型分层翻译；批量生成 + 自动预检 | 30 份样本、评测表 |
| 展示 | `docs/` | GitHub Pages 交互演示页 | 在线可点 |

**为什么指标从 11 个砍到 7 个**：相关性审计发现「年化收益 / 超额收益 / 费后年化」三者 Spearman 相关为 1.00，直接加权等于给收益维度记了三遍分。

## 在线演示 / 本地运行

**演示页**：打开 [`docs/index.html`](docs/index.html)（或访问上方 badges 里的在线链接）。
可切换 6 只对照基金与 15% / 30% 两档风险承受线，页面上的每个数字都由 `card.py` 现算并固化成 `docs/data.js`。

```bash
git clone https://github.com/Estrella-lc/fund-checkup.git
cd fund-checkup
pip install -r requirements.txt

# 方式一：不需要任何 API Key，直接看数据卡（1 秒）
python src/card.py --code 012414 --risk 15

# 方式二：复现全部分析（需已有 data/raw，约 1 分钟）
python src/step4_indicators.py    # 28s → 5,085 只
python src/step5_cluster.py       # 17s → 聚类 + 高费低效
python src/step6_eda.py           # 15s → 8 张图

# 方式三：重新生成演示页数据
cd src && python build_demo.py
```

从零采集全量数据需数小时，且 akshare 接口会变（部分接口已改过字段名），建议先 `--limit 200` 小样本试跑；采集失败记录在 `data/raw/failed*.log`，脚本支持断点续传。

**AI 层（可选，需自备 Key，OpenAI 兼容接口）**

```bash
export LLM_API_KEY=your_key
export LLM_API_BASE=https://open.bigmodel.cn/api/paas/v4
export LLM_MODEL=glm-4-flash
python src/step7_ai_report.py --code 012414 --query "每月投2000元，最多接受15%回撤"
```

Key 仅通过环境变量注入，不写入任何文件；`.env*` 已在 `.gitignore` 中。

## 数据口径

| 项 | 口径 |
| --- | --- |
| 样本 | 主动权益 4,109 只 + 被动指数 976 只 = 5,085 只（要求 7 项指标齐全） |
| 区间 | 2023-10 至 2026-10，快照 **2026-11-10** |
| 收益 | 复权净值增长率年化 |
| 费率 | 管理费 + 托管费 + 销售服务费；赎回费单列（随持有期变动） |
| **超额收益** | **年化收益 − 同组中位数（同类相对），不是相对业绩比较基准** |
| 高费低效 | 综合费率 ≥ 行业标准档（主动 1.40% / 被动 0.60%）**且** 卡玛处于组内后 25% |
| 风险调整收益 | 卡玛（年化收益 / 最大回撤）；未纳入无风险利率，故未算夏普 |

## 已知局限

写清楚"这套东西不能回答什么"，比多堆十个指标更重要。

- **不含持仓数据**：无重仓股、行业分布、换手率，因此不做任何"选股能力"判断，只做净值与费率维度的横向筛查。
- **不含跟踪误差**：指数基金的跟踪质量无法直接评估。
- **只有近三年单一区间**：无分年度收益，无法验证"超额是集中在某一年行情，还是跨年稳定"——而这恰是区分运气与能力的关键证据。
- **规模覆盖 60.7%**（3,085/5,085），规模相关判断只在有数据样本内进行。
- **聚类轮廓系数 0.27**：画像标签作描述性分组，不宣称显著结构。
- **未计算夏普**：卡玛只用回撤做分母，不惩罚上行波动，口径需注明。

## 评测结果（AI 层）

| 指标 | 结果 |
| --- | --- |
| 合规违规词 | 0 / 30 |
| 免责声明覆盖率 | 30 / 30 |
| 报告级事实错误 | **7 / 30（23%）** |
| 错误模式 | 前提错配 3、逻辑反转 2、算术幻觉 2、分位误用 1 |
| 单次生成成本 | 约 0.0002 元（glm-4-flash） |

错误不是随机噪声，而是系统性模式，因此迭代方向明确：把差值放进上下文由代码算、加正负例对照、禁止默认假设数字参与计算。7 处真实错误的逐条归因见 [`reports/11_全流程复核与缺陷清单.md`](reports/11_全流程复核与缺陷清单.md)。
